# 文案精简口径与计划模板

## 一、保留清单（一律不动）

- 全部数值：月搜索量、月购买量、购买率、商品数、需供比、SPR、CPC、价格带、销量、销售额、BSR、评分数、评分、上架天数、占比、同比、峰谷比、成本、税率。
- 全部英文关键词与搜索词，包括 `pet harness`、`escape proof pet harness`、`holiday socks` 这类长尾词。
- 类目路径、节点编号、ASIN、商品 URL、listing 原始标题、埋词清单。
- 表头、章节标题、序号、风险等级、数据来源列、日期。
- 结论与建议本身、可执行动作、口径声明。
- 图片、DISPIMG 公式、超链接、合并单元格、数字格式、行高列宽。

数值保持原始精度，不因精简而取整。统计占比按惯例写成整数百分比，但源数据里的购买率、增长率、需供比保留小数。

## 二、删除清单

- 分析文案里的品牌罗列：`rabbitgoo`、`Aevyri`、`Fida`、`matilor`、`BUENWAZ`、`BISOUSOX` 等。改成「头部一款」「有新品」「竞品」。
- 推导过程：把同一个数字在不同格子里反复解释一遍的句子。
- 重复强调、铺垫句、三段式排比、`体现了` / `凸显了` 这类浅层分析。
- 冗余修饰：`极具视觉冲击力`、`完美契合`、`建立明确差异化定位`、`附加情绪价值`、`值得关注的是`。
- 把 C 列数据换词复述成 D 列的「总结分析」。
- 运营黑话，见下一节。

## 三、黑话替换清单

| 不用 | 换成 |
|---|---|
| 甜点带 / 甜点词层 | 这一档 / 销量最集中的价格带 |
| 红海 / 内卷 / 蓝海 | 低价竞争 / 供给过剩 / 还没人做 |
| 天花板 / 腰部 | 销量上限 / 中间那一层 |
| 卡位 / 截流 / 爬坡 / 护城河 | 占住位置 / 接住流量 / 起量阶段 / 别人不容易复制的地方 |
| 绝对入口 / 红利期 / 洗牌市场 | 用词要具体，别造四字词 |
| 一超多强 / 三峰一谷 / 倒金字塔 / 中高集中 | 直接写事实，例如「一年有三个旺季」 |
| 没戏 / 硬打 / 死路 / 打不动 / 白捡 / 吃长尾 | 行不通 / 广告太贵 / 还有空间 / 投不起 / 就能接住 / 接长尾流量 |

**自创四字词和隐喻一律不用**。表格文案写成「一年三个旺季」「新款不断冒出来」「价格能站上去的一档」这种直白说法。

## 四、禁用符号与格式偏好

- 禁用：长破折号 `——`、中文引号 `「」`、箭头 `→`、圈号 `①②③`、中文语境下的半角括号 `()`。
- 改用：逗号 `，`、标准中文双引号 `“”`、编号 `1. 2. 3.`、全角括号 `（）`。
- 表格朴素、非 AI 感，避免过度规范化版式。
- 不冻结窗格；行高要能完整显示内容；全表开 `wrap_text`。
- 金额用 `$#,##0.00`，百分比用 `0.0%` 数字格式。
- 统一用短陈述句，不带分号堆叠、编号展开和括号补充，各行措辞风格一致。

## 五、品牌名的处理边界

| 位置 | 处理 |
|---|---|
| 分析文案、总结分析、备注说明 | 删掉，改成通用表述 |
| 原始数据表的商品标题 | 保留，它是识别依据 |
| listing 标题埋词清单 | 保留 |
| 商品 URL | 保留 |
| 合规表的商标检索清单、专利避让清单 | 保留，它是检索依据；交付时说明为何保留 |

删品牌名时**不要顺手删掉跟着它的数据**，例如「rabbitgoo 单款 65,620 条评论、143 个变体」改成「头部单款 65,620 条评论、143 个变体」。

## 六、力度对照

| 力度 | 被改写文案保留率 | 适用场景 |
|---|---|---|
| 全精简 | 45% 到 55% | 用户说「别写这么多」「像人工整理的表」 |
| 半精简 | 82% 到 90% | 用户说「不要精简这么多」「搜索词和搜索量还是要写」「总结分析写多一些」 |
| 删废话 | 65% 到 75% | 用户只嫌啰嗦，没要求大改 |

超过 50% 的删减通常意味着删掉了内容而非废话，要回头检查。低于 10% 的删减要确认是否真的达成了用户的诉求。

## 七、计划模板（步骤 2 用）

用户要求先列计划时，按六节输出，且明确写「没有改动任何文件」：

1. **文件现状**：Sheet 数、文本格数、字数、图片与公式、数据表占比、禁用符号现状。
2. **精简口径**：保留清单、删除清单、目标保留率、符号与黑话处理。
3. **逐表范围**：一张表一行，写明哪些格改、哪些列不动、数据表整表保留。
4. **技术路线**：为什么必须 XML 直改、sharedStrings 怎么处理、其余条目如何保留。
5. **交付与校验**：新文件名、备份位置、校验项清单。
6. **需要确认的点**：给 3 到 4 个，每条附默认建议，让用户能回「按默认来」。

常用四个确认项：

1. 力度：按某个保留率，还是更明显一些。
2. 品牌名：是否全删，原始数据表与 listing 标题是否保留。
3. 孤立数字或模板残留：保持原样还是清理。
4. 黑话与符号：是否顺手统一。

## 八、交付回复要点

- 新文件路径、原件未改、备份位置。
- 改写格数与覆盖表数。
- 力度口径要说清是「被改写文案」还是「全文件」，并解释全文件字数几乎不变的原因。
- 品牌、黑话、符号残留统计，以及有意保留项的解释。
- 图片、公式、数据表字节级完整性结论。
- 不要罗列每一格改了什么，除非用户要求。
